## How to interpret status

- **REAL / PRESERVE** = present in actual managed source with a genuine task/workbook/calendar data path; no claim of UAT acceptance.
- **PARTIAL / DESIGN PARITY GAP** = some genuine behavior exists, but the approved Review 08 visual/interaction treatment is not in app.
- **ABSENT / FUTURE FUNCTIONAL CONTRACT** = approved as a design concept only; functional scope/data model/implementation authorization pending.
- **EXCLUDED / DEFERRED** = explicitly out of existing authorized scope or staged for later in [roadmap #1](https://github.com/Kenny619/spl-wbs/issues/1).
- **VERIFY** = further exact-head and physical UX testing required.

**NOT YET FUNCTIONALLY AUTHORIZED:** permanent Meeting Review workflow, persistent Under Watch, risk/Green algorithm, automatic commitment-impact baselines/acceptance, new workbook sheets/fields, arbitrary schema migrations and new project-owned blackout storage.

## 3. Concrete approval conflicts / sequence

1. **Calendar UI versus storage (owner selected A: UI-only session-scoped relocation).** Approved Review 08 **places blackout controls in Settings**, but older [#20](https://github.com/Kenny619/spl-wbs/issues/20) and Stage D [roadmap #1](https://github.com/Kenny619/spl-wbs/issues/1) defer **project persistence** and instruct v1 to keep its **session-scoped controls in Gantt**. Most constrained reconciliation: freeze the *design location* now; propose a **UI-only relocation** which keeps existing session-scoped state, says “Session only,” and leaves project-backed persistence strictly to Stage D. This relocation must be separately bounded/authorized before production coding and preserve the existing calendar math.
2. **Meeting Review visual versus implementation boundary (owner selected B: integrate with real Watch, no status-only interim).** Review 08 shows it; [DES-010 UI-INT approval](21_D3_PO_APPROVAL_A_B.md) explicitly excludes new permanent Meeting Review business workflow. Do not build in current PR #37 as incidental report/UI work. See [Meeting proposal](24_MEETING_REVIEW_FUNCTIONAL_PROPOSAL.md).
3. **Under Watch versus TaskStatus and Report 1.1 (owner chose shared state + reason-backed Watch/Clear/Unknown + low-friction clearance).** Current statuses At Risk/Blocked are not persistent reasons or Green. [Risk concept](05_RISK_WATCH_MODEL.md) is exploratory and [Report 1.1 frozen contract](https://github.com/Kenny619/spl-wbs/issues/7) forbids invented manual RAG. See [Watch proposal](25_UNDER_WATCH_FUNCTIONAL_PROPOSAL.md).
4. **Schedule filtered-columns behavior.** A filter indicator/count is owner-approved as part of design; implementation must not claim done because the v18 engine counts selected values and only supports 4 filter dimensions. Start/Finish/Progress semantics on visible columns need an explicit technical contract before declaring parity.
5. **Latest-code test provenance.** Prior CI green for exact SHA `85218fd...` does not automatically validate the current `04e31d...` head or future UI amendments. No physical corporate Edge validation is inferred.
